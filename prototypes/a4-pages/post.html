Drawing a million points: notes on time-series visualisation

What has to happen between a database full of samples and a chart that stays readable while you zoom.

14 Sep 20269 min readPlaceholder post: layout sample, text is not final

A screen is roughly two thousand pixels wide. A day of sensor data at ten samples a second is eight hundred and sixty-four thousand points. Something has to give, and the interesting question is what.

Decide what the chart is for

Before choosing an algorithm, decide what a reader should be able to spot. If it is spikes, an average will hide them. If it is trend, drawing every point is noise. Most arguments about charting libraries are really arguments about this.

A chart is a claim about the data. Downsampling decides which claims you are able to make.

A minimal min/max downsampler

The simplest approach that keeps spikes: split the visible range into one bucket per pixel column, and keep the minimum and maximum of each.

function minMax(xs: Float64Array, ys: Float64Array, buckets: number) {
  const out: [number, number][] = [];
  const size = Math.ceil(xs.length / buckets);
  for (let b = 0; b < buckets; b++) {
    let lo = Infinity, hi = -Infinity, iLo = 0, iHi = 0;
    for (let i = b * size; i < Math.min((b + 1) * size, xs.length); i++) {
      if (ys[i] < lo) { lo = ys[i]; iLo = i; }
      if (ys[i] > hi) { hi = ys[i]; iHi = i; }
    }
    // keep time order so the line does not zig-zag
    const pair = iLo < iHi ? [iLo, iHi] : [iHi, iLo];
    pair.forEach(i => out.push([xs[i], ys[i]]));
  }
  return out;
}
